ROLEPLAY DIARY - WHAT EVERY FILE DOES
=====================================

A plain-language map of the project.


THE BIG IDEA: MODEL, VIEW, CONTROLLER
-------------------------------------
Three files, each with one job.

  model.py       THE DATA.  Characters, their stories and photos, how all of
                 that is saved and loaded, and how it is turned into a PDF.
                 Knows nothing about windows or buttons.

  view.py        THE SCREEN.  Every window, button, colour and dialog.
                 Draws what it is handed, and reports what you clicked.
                 Never saves anything and never decides anything.

  controller.py  THE MIDDLE.  Listens to the view, tells the model what to
                 change, then tells the view what to draw. The only file
                 that knows about both of the other two.

The rule that keeps it honest is written at the top of model.py: that file
must never import tkinter. Because it does not, the entire data side can be
run and checked from a plain script with no window on screen.

Every action in the app follows the same path:

  you click something
     -> view tells controller what happened
     -> controller asks model to change something
     -> controller tells view what to draw now


THE THREE FILES, IN MORE DETAIL
-------------------------------

model.py       (about 1400 lines)

    Choices          Alive / Deceased / Shelved, and the entry kinds like
                     Milestone, Career, Injury. Stored as numbers, shown as
                     words, so rewording one never disturbs saved data.

    Dates            Two readers. One copes with the old C# date format so
                     your existing diary still opens. The other is the
                     forgiving one that accepts "20 June 2026", "2026-06-20"
                     or "today", and just saves the entry undated if it
                     cannot make sense of what you typed.

    Character,       The nouns. Each also knows how to describe itself - a
    DiaryEntry,      Character can produce its own initials for the blank
    CharacterPhoto   portrait, or the grey summary line under its name.

    AppPaths         Decides where everything is stored, and creates the
                     folders on first run.

    Database         Opens the database file and brings its structure up to
                     date. The structure is a numbered list of steps: a new
                     user runs step 1 and gets the tables, an existing user
                     is left alone. GOLDEN RULE, written in the file: never
                     edit a step that has already shipped.

    Repositories     The only place that writes SQL. One class per table,
                     with plain methods like get_all, insert, delete.

    PhotoStorage     COPIES pictures into the diary's own folder rather than
                     remembering where they were. That is why you can delete
                     the original screenshot a year later and still have it.

    PdfExporter      Builds the exported document: cover page with the
                     portrait, then profile, background, timeline, gallery.

    Diary            The front desk. One object with everything the
                     controller is allowed to ask for. The controller never
                     sees a database connection or writes a line of SQL.


view.py        (about 1900 lines)

    Palette          Every colour in the app, each with a name. No other
                     part of the code writes a colour code. A light theme
                     would mean editing this one class.

    Fonts            The handful of text sizes, built once.

    Images           Loads pictures and rounds their corners. Also keeps
                     hold of them, because tkinter silently throws away any
                     image nothing is holding on to.

    Building blocks  tkinter gives you none of these, so they are built by
                     hand: Button (rounded, drawn on a canvas), Chip, Pill,
                     Dot, Avatar, Field (with placeholder text), TextArea,
                     Dropdown, Card, TabBar, EmptyState, ScrollFrame and a
                     slim scrollbar. Build new screens from these, or the
                     dark theme will not hold together.

    CharacterDialog  The create/edit character window, including attaching
                     photos before the character even exists yet.

    EntryDialog      The add-a-story-entry window, with the live hint that
                     tells you how your date was understood.

    Message, Ask     Confirmations, and the native file pickers.

    Handlers         THE IMPORTANT ONE. A list of everything the view can
                     report - new_character, delete_entry, export_pdf and so
                     on. This list is the whole contract between the view
                     and the controller. Read it and you know what the app
                     can do.

    MainView         The main window: the character list down the left, the
                     open character on the right with its three tabs.


controller.py  (about 390 lines)

    DiaryController  One handler per item in that Handlers list, each only a
                     few lines long. Holds the running state - what is
                     searched for, which filter is on, who is open - and a
                     single _refresh() that decides what is on screen.

    Crash handling   Unexpected errors are written to crash.log so a problem
                     leaves evidence instead of just vanishing.

    main()           The entry point. Running "python controller.py" starts
                     the app.


THE REST OF THE FOLDER
----------------------

RoleplayDiary.pyw   The file you double-click to run the app. That is all it
                    does. The ".pyw" ending stops a black console window
                    appearing behind it.

requirements.txt    The two outside packages needed: reportlab (makes the
                    PDF) and pillow (reads image files). Install them with:
                        pip install -r requirements.txt
                    The interface needs nothing - tkinter comes with Python.

pyproject.toml      The project's ID card: name, version, dependencies.

README.md           The manual.

.gitignore          Tells Git what must never be uploaded. Most importantly
                    YOUR DIARY - the database, photos and exported PDFs all
                    stay on your machine.

FILES.txt           This file.

Deepwell/           NOT part of Roleplay Diary. A separate Godot game
                    project that happens to live in the same folder.


IF YOU WANT TO CHANGE SOMETHING
-------------------------------

A colour, or the whole look ........... view.py, the Palette class
Wording on a button or a screen ....... view.py
The new-character form ................ view.py, CharacterDialog
What happens when a button is pressed . controller.py
How the PDF looks ..................... model.py, PdfExporter
Where files are saved ................. model.py, AppPaths

Add a new field to a character, in order:
    1. model.py - add it to the Character class
    2. model.py - add a NEW numbered step to Database.MIGRATIONS
    3. model.py - save and load it in CharacterRepository
    4. view.py  - add the input to CharacterDialog
    5. view.py  - show it in the character's header


WHERE YOUR ACTUAL DIARY LIVES
-----------------------------
None of it is in this project folder. It is all here:

    %AppData%\RoleplayDiary

        roleplaydiary.db     the database - characters, entries, photos
        media\               the copied-in picture files
        exports\             PDFs you have exported
        crash.log            only appears if something went wrong

Copy that one folder to back up everything. It is created for you the first
time you run the app - there is nothing to set up.
